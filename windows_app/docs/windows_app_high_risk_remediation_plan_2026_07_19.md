# Windows 端高风险问题整改实施方案

方案日期：2026-07-19。

状态：待实施。本方案覆盖近期复审确认的五项高风险问题：患者权限、采购与预约失败关闭、MySQL 删除与恢复原子性、持久化同步、退出登录会话清理。

## 1. 目标与边界

### 目标

1. 非管理员只可读取其医生字段对应的患者及关联业务数据。
2. 用户、权限 Provider 或医生字段缺失时失败关闭，不得视为管理员。
3. MySQL 删除与恢复失败时不遗留部分数据或关闭的外键检查。
4. SQLite → MySQL 同步可在断线、进程退出后恢复，不再由不可等待的后台 microtask 静默丢弃。
5. 登出后不保留上一位用户的身份、权限、缓存或页面状态。

### 不纳入本方案

- 保留新数据库默认管理员 `admin / 123456` 的首次登录；强制首次改密另行决策。
- 主人已确认保留“记住用户名密码”的本地明文存储。
- 登录页默认凭证预填、明文日志、开发机绝对路径、动态 SQL 字段白名单属于后续规范治理，不混入本轮。
- 不修改 Android 端。

## 2. 核心设计

### 2.1 权限统一与失败关闭

SQLite/MySQL 患者数据源的全量、分页、搜索、按 ID 查询统一复用同一医生条件。只有明确管理员可跳过过滤；无用户、无 Provider、无医生字段、权限解析异常一律返回空结果。

Dashboard、导出、预约表单、财务患者检索不得通过专用全量接口绕过权限。

### 2.2 MySQL 原子性

患者删除使用单一事务完成关联记录和患者本体删除，删除 `FOREIGN_KEY_CHECKS = 0` 的最终依赖。恢复前验证备份和目标连接；失败不可报告为成功或保留半恢复状态。

若转储含 DDL 导致 MySQL 事务不能覆盖完整恢复，实施前应采用临时库验证后切换的可恢复流程，并在实施记录中说明实际边界。

### 2.3 持久化同步

推荐增加 SQLite 同步任务表，字段至少包含模块、实体、操作、主键、载荷、状态、尝试次数、最后错误、创建与完成时间。业务写入和任务入队必须在同一 SQLite 事务；统一执行器按顺序领取、成功确认、失败保留并退避重试。

这是数据库 schema 变更，未经主人单独确认不得实施批次 4。

### 2.4 会话清理

新增唯一登出入口，清空 UserProvider、DatabaseProvider 和患者、预约、采购、财务、病历、材料等 Provider 的当前用户、权限与缓存；清理成功后才导航至登录页。

## 5. 批次 1：患者读取权限

### 实施

1. SQLite/MySQL `getAllPatients` 复用既有权限条件构建器。
2. 无用户且无医生明确建模为无访问，不允许因 `doctorName == null` 得到全量数据。
3. 用户切换时先失效缓存，再重建带权限的数据源。
4. Dashboard、导出、预约表单和财务检索均改走受限入口。

### 测试

- SQLite：管理员、医生甲、医生乙、无用户、无医生用户分别验证全量、分页、搜索、按 ID、导出。
- MySQL：同一数据集验证相同行为；真实连接保留人工回归。
- 医生甲不能得到医生乙的 ID、姓名、统计或导出数据。

## 6. 批次 2：采购与预约失败关闭

### 实施

1. 采购 `_getDoctorFilter` 对缺少 Provider 或当前用户返回集中定义的无访问过滤值。
2. 预约 `_applyPermissionFilter` 对缺少 Provider 或当前用户返回空列表。
3. 预约状态服务在未登录或医生字段缺失时不走全量加载。
4. 清理重复魔法字符串，改为模块语义常量。

### 测试

- 管理员可查看全量，医生仅查看本人。
- 用户 Provider、当前用户或医生字段缺失时，采购计数／列表／搜索、预约列表均为空。

## 7. 批次 3：MySQL 删除与恢复一致性

### 实施

1. 患者及关联数据在单一 MySQL 事务内删除，任一步失败即回滚。
2. 删除所有 fire-and-forget 删除路径中对外键检查的手动关闭；若临时保留，必须在 `finally` 恢复。
3. 恢复前校验备份文件；恢复失败时明确失败，不能把部分成功报告为完成。
4. 保留恢复前备份；若 DDL 不可事务化，使用隔离验证与可恢复切换。

### 测试

- 模拟关联删除中途失败，断言数据未改变且外键检查开启。
- 模拟恢复 SQL 失败，断言不报告成功。
- SQLite 既有恢复测试继续通过；MySQL 恢复列为人工回归。

## 8. 批次 4：持久化同步任务

### 前置确认

新增 SQLite 同步任务表和迁移属于数据库 schema 变更。未经主人确认，本批次维持阻塞。

### 确认后实施

1. 新增任务表、状态索引与去重键。
2. 患者、预约、财务、采购、材料、病历的 SQLite 写入与任务入队置于同一事务。
3. 增加统一任务执行器，支持依赖顺序、重试、退避、启动和前台恢复。
4. 逐步删除各模块 fire-and-forget `Future.microtask` 同步入口。

### 测试

- 断线写入后任务保留，重连后只执行一次。
- 模拟重启可恢复未完成任务。
- 连续更新只同步最终版本，删除不被旧更新覆盖。
- MySQL 失败不丢失 SQLite 数据或任务。

## 9. 批次 5：登出会话清理

### 实施

1. 为 UserProvider 与 DatabaseProvider 增加可验证的会话清理 API。
2. 各业务 Provider 提供统一的登出／用户切换缓存清理入口。
3. 登出确认后先 `await` 清理，再导航到 `/login`。
4. 登录成功后仅按新用户初始化数据源与缓存。

### 测试

- 管理员登出后，所有 Provider 无当前用户、无列表和无权限缓存。
- 管理员→医生、医生甲→医生乙切换后不显示旧缓存。
- 清理失败时不导航到伪登出状态。
