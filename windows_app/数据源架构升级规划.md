# Windows端数据源架构升级规划

## 总体目标
将Windows端所有Provider统一升级为：**数据源模式 + 缓存机制 + MySQL动态连接获取**，与安卓端保持一致的架构。

## 核心原则
1. **谨慎变更** - 最小化代码更改，保持现有功能完整性
2. **向后兼容** - 确保现有API接口不变
3. **渐进升级** - 一个模块一个模块进行，降低风险
4. **统一架构** - 所有模块采用相同的数据源模式
5. **智能初始化** - 根据配置模式一次性正确初始化，避免重复初始化

### 2. Provider架构模式
```dart
class [Module]Provider extends ChangeNotifier {
  // 数据源实例
  Sqlite[Module]DataSource? _sqliteDataSource;
  MySql[Module]DataSource? _mysqlDataSource;
  
  // 缓存机制
  List<[Model]>? _cachedRecords;
  DateTime? _lastCacheTime;
  static const Duration _cacheValidDuration = Duration(minutes: 20);
  
  // 连接状态
  bool _isConnected = true;
  String? _lastError;
  
  // 数据库提供者引用
  dynamic _databaseProvider;
  
  // 获取当前数据源
  [Module]DataSource get _currentDataSource { ... }
  
  // MySQL动态连接获取
  MySqlConnection? get _currentMysqlConnection { ... }
  
  // 缓存管理
  bool _isCacheValid() { ... }
  void _updateCache(List<[Model]> records) { ... }
  void clearCache() { ... }
  
  // 智能初始化（支持模块化配置）
  Future<void> initializeFromDatabase(
    dynamic dbProvider, {
    Map<String, String>? moduleDataSources,
    String? dataSourceMode,
  }) async { ... }
}
```

### 3. 智能初始化流程
在 `main.dart` 中为所有Provider添加智能的初始化调用：

#### A. ChangeNotifierProxyProvider中的初始化
```dart
ChangeNotifierProxyProvider<DatabaseProvider, [Module]Provider>(
  create: (_) => [Module]Provider(),
  update: (_, dbProvider, provider) {
    provider ??= [Module]Provider();
    
    // 获取设置提供者以获取模块配置
    final settings = Provider.of<SettingsProvider>(_, listen: false);
    final dataSourceMode = settings.dataSourceMode ?? 'global';
    final moduleDataSources = settings.moduleDataSources ?? {};
    
    // 智能初始化：根据配置模式决定数据源类型
    provider.initializeFromDatabase(
      dbProvider,
      moduleDataSources: moduleDataSources,  // 模块配置
      dataSourceMode: dataSourceMode,        // 配置模式：'global' 或 'modular'
    );
    
    return provider;
  },
)
```

#### B. Provider内部的智能初始化逻辑
```dart
Future<void> initializeFromDatabase(
  dynamic dbProvider, {
  Map<String, String>? moduleDataSources,
  String? dataSourceMode,
}) async {
  // 确定要使用的数据源类型
  String dbType = 'sqlite';
  
  // 如果是模块化模式且有模块配置，优先使用模块配置
  if (dataSourceMode == 'modular' && 
      moduleDataSources != null && 
      moduleDataSources.containsKey('[moduleName]')) {
    dbType = moduleDataSources['[moduleName]']!;
    print('[Module]Provider使用模块化配置: [moduleName] -> $dbType');
  } else {
    // 否则使用全局配置
    dbType = dbProvider.dataSourceType ?? 'sqlite';
    print('[Module]Provider使用全局配置: $dbType');
  }
  
  // 一次性初始化正确的数据源
  if (dbType == 'sqlite') {
    // 初始化SQLite数据源
  } else if (dbType == 'mysql') {
    // 初始化MySQL数据源
  }
}
```

**配置模式逻辑：**
- **全局模式 (`dataSourceMode = 'global'`)**：所有模块使用全局配置的数据源
- **模块化模式 (`dataSourceMode = 'modular'`)**：每个模块根据`moduleDataSources`配置使用指定的数据源
- **一次初始化**：避免先全局后模块的重复初始化，直接根据最终配置初始化正确的数据源
- **避免重复**：只在ChangeNotifierProxyProvider中初始化，不在其他地方重复调用

## 技术要点

### 1. MySQL动态连接获取
```dart
MySqlConnection? get _currentMysqlConnection {
  if (_effectiveDataSourceType != 'mysql' || _databaseProvider == null) {
    return _mysqlConnection;
  }
  
  try {
    final latestConnection = _databaseProvider.mysqlConnection;
    if (latestConnection != null) {
      _mysqlConnection = latestConnection;
      return latestConnection;
    }
  } catch (e) {
    print('获取最新MySQL连接失败: $e');
  }
  
  return _mysqlConnection;
}
```

- **缓存时长**：20分钟
- **缓存策略**：读取时检查缓存有效性，修改时清除缓存

### 3. 连接测试
```dart
Future<bool> _testMySqlConnection() async {
  if (_currentMysqlConnection == null) return false;
  
  try {
    await _currentMysqlConnection!.query('SELECT 1').timeout(
      const Duration(seconds: 10),
    );
    _isConnected = true;
    _clearError();
    return true;
  } catch (e) {
    _setError('MySQL连接测试失败: $e');

  }
}
```

### ⚠️ **常见问题预防**

#### 1. **重复初始化问题**
- **症状**：同一个Provider初始化多次
- **原因**：在ChangeNotifierProxyProvider和_initializeDatabase中都调用了初始化
- **解决**：只在ChangeNotifierProxyProvider中初始化，移除其他地方的调用

#### 2. **模块配置传递问题**
- **症状**：Provider显示"模块配置: null"
- **原因**：ChangeNotifierProxyProvider中没有正确获取和传递模块配置
- **解决**：在update方法中正确获取SettingsProvider并传递配置

#### 3. **MySQL DateTime转换问题**
- **症状**：`type 'DateTime' is not a subtype of type 'String'`
- **原因**：MySQL返回DateTime对象，但模型期望字符串
- **解决**：在MySQL数据源中添加`_convertRowToMap`方法处理转换

#### 4. **数据源选择逻辑问题**
- **症状**：模块没有使用正确的数据源
- **原因**：initializeFromDatabase中的数据源选择逻辑错误
- **解决**：优先检查模块化配置，然后回退到全局配置
