## 保留边界

- 现用预约模型为 `models/database_models.dart`，患者数据源为 `data_sources/patient_data_source.dart`，Schema 校验为 `utils/schema_validator.dart`。
- 财务清理保留 `FinancialDataCleanerService`；消息提示保留 `MessageToastHelper` 与现用 Toast Manager；数据库配置和连接保留 `DatabaseSwitchService`、`DatabaseProvider` 与现用连接服务。
- 设置保留 `themeMode` 读取、`getThemeMode()`、预约提醒读写；采购页保留所有实际调用 `_loadData` 的刷新入口。

## 暂缓项目

### 现用重复逻辑专项

- **4A 财务新增／编辑表单：随相关需求实施。** 两个弹窗的表单布局、校验和输入逻辑重复，长期有维护价值；但默认值、保存对象和日期初始化存在业务差异。下次修改收费项目表单时，先补覆盖空名称、无效金额、项目类型切换、保存成功／失败、关闭弹窗的回归测试，再提取共享表单。
- **4B 牙齿状况展示：随牙齿展示需求实施，优先级高于 4A。** 患者详情与病历详情的牙位十字图和备注展示高度重复，适合收口为只读展示组件；但两处牙位数据来源与 `chartPrefix` 取得方式不同，错误抽取可能导致病历显示错位。实施前必须覆盖四象限、单象限为空、仅备注、历史多日期、旧格式 Map 缺键／null，以及两个页面展示一致性。
- **4C 图表骨架与日期范围：不纳入计划。** 月度收费与加工费图表的数据结构、信息密度和视觉语义不同；财务与采购日期范围的初始值和统计口径也未确认一致。当前仅有结构相似，抽取会形成高参数化组件，收益不足。仅在统计页改版、明确要统一产品规则或出现实际缺陷时另立方案。

### 批次 6：MySQL ResultRow 转换收口

暂缓。其目标是将多个数据源中的 `DateTime`、Blob、`Uint8List`、UTF-8 容错与空值转换收口至 `MysqlRowProcessor`。当前处理器与部分现用数据源语义不一致：图片字段的字节／字符串表示、UTC 本地化和普通 Blob 保留策略均可能不同；且实际同类转换点多于原计划列出的范围。

没有明确的 MySQL 转换缺陷时，不以“减少重复代码”为由迁移。后续如出现图片、文本或日期转换不一致，应另立专项：先定义统一语义，建立覆盖图片字节、普通文本 Blob、空值、畸形 UTF-8 和日期的对照测试，再逐数据源迁移。

### 批次 7：统计面板、连接访问器和确认对话框治理

暂缓并按业务需求拆分，不作为清理任务推进：

- 统计卡片统一的收益主要是视觉一致性；仅在统计页改版时评估主题化面板组件。
- MySQL 连接访问器涉及 Provider、初始化、缓存回退与断线重连生命周期，属于跨模块架构调整，需单独设计与验证。
- 设置确认框存在转发包装；删除确认框的现代实现已承担主要页面调用，旧实现仍被同步日志页使用。未来修改该页面时再一并迁移即可。
